# 3D 人体器官 · 可行性与功能规划

> 状态：已上线代码。2026-11-20 改为**写实人体**（BodyParts3D + HuBMAP 肺，见 8.1），代码生成的人体留作下载失败时的兜底。目标用户是小学生，帮孩子知道「器官在身体哪里、长什么样、在做什么」。
> 不出作业、不打印。交互方式参考「3D 太阳系」：能转、能点、能拆开、能看动画。
>
> 已确认（2026-11-20）：
> - 做**一个完整的人体模型**，皮肤、骨骼和所有大器官都在里面，可以一层层剖开、把器官展开来看；不细到神经细胞、血管网这类细节。
> - 工作演示只做常规的大知识点：**心脏泵血、肺呼吸、食物旅行（消化）**。其他器官能点、能看名字和一句话说明，没有动画。
> - 身体用半透明「玻璃人」风格。
> - 不做「真实模型」开关。一期全部用代码生成；用下来觉得不够真实直观，已换成写实模型（8.1），没有开关，下载不到时自动用代码生成的。

## 1. 结论

**可行，而且能跑得流畅**，前提是用**代码生成卡通风格的低面数器官**，不直接用开源的医学模型。

- 小程序里 three.js + WebGL 已经在「3D 太阳系」「3D 几何体」跑通，新工具放进同一个 `subsolar` 分包就能直接用 three.js，不增加主包体积。
- 代码生成器官没有模型文件，预计只多 80～120 KB 代码；`subsolar` 分包现在约 680 KB，离 2 MB 上限很远。
- 全身同屏控制在约 4～6 万个三角形，中低端安卓机也能稳定 60 帧（太阳系目前量级相当）。
- 心跳、呼吸、肠道蠕动这些动画在代码模型上做最容易：直接改缩放、改顶点，不需要骨骼绑定。
- 已决定不用开源医学模型，原因见第 3 节。

## 2. 两个知识点要先纠正

需求里的两个说法和小学科学教材不一致，做的时候按教材讲：

| 需求原话 | 正确说法（工具里这样讲） |
| --- | --- |
| 心脏跳动造血 | 心脏是「水泵」，把血液**泵**到全身；血液是**骨髓**造的。可在骨骼里加一句「骨头里的骨髓会造血」。 |
| 大肠消化 | 消化和吸收营养主要在**小肠**；大肠主要**吸收水分**，把剩下的变成大便。 |

## 3. 参考项目评估

| 项目 | 模型来源与许可 | 体积 | 能不能用 |
| --- | --- | --- | --- |
| [open-anatomy-3d](https://github.com/MervinR07/open-anatomy-3d) | BodyParts3D 等，模型 **CC BY 4.0**（可商用，需署名并注明修改），代码 MIT | 全身一个文件 7.6～8.1 MB | 许可可以；文件远超分包 2 MB，只能云存储，且整体太重 |
| [human-atlas](https://github.com/tahfimism/human-atlas) | BodyParts3D 4.0，**CC BY 4.0**，代码 MIT | 全身约 33 MB；单器官：心 397 KB、肺 431 KB、肝 463 KB、脑 453 KB、胃 34 KB、肾 59 KB | 许可可以；单个器官可用，但 8 个主要器官合计约 2.3 MB，仍超分包 |
| [3d-human-body-anatomy](https://github.com/SeemaBansal1/3d-human-body-anatomy) | Z-Anatomy，**CC BY-SA 4.0**（相同方式共享），部分参考素材还有 **NC（禁止商用）** | 每个系统 0.8～1.9 MB | **不用**：SA 会要求衍生作品同许可，NC 素材不能商用 |
| [human-anatomy-explorer](https://chowbees.github.io/human-anatomy-explorer/) | 运行时从 HuBMAP / jsDelivr 拉 CC BY 4.0 模型，仓库本身不带模型、没有许可证 | — | 只参考交互，不拿代码 |

医学模型不适合直接做一期的原因：

1. **体积**：分包上限 2 MB，主要器官加起来就超了，只能放云存储，首次进入要下载 2～3 MB，弱网体验差。
2. **解码**：这些模型多用 Draco / Meshopt 压缩，小程序里没有 Worker 版解码器（Draco 依赖 wasm），要额外适配 GLTFLoader 和解码器，代码也要再加 100 KB 以上。
3. **风格**：医学写实风格对小学生偏吓人，细节太多反而看不出重点。
4. **动画**：静态模型没有骨骼和形变目标，要做心跳、蠕动还得再加工。
5. **许可**：CC BY 4.0 要在小程序里显示署名并说明「已修改」，可以做到，但每个文件都要登记。

**决定**：全部代码生成。以后如果想加「真实模型」开关，只选 **BodyParts3D 4.0（CC BY 4.0）**，先在电脑上减面到每个器官约 3000～5000 个三角形、去掉压缩，放 `cloud-storage/`，用 `cloudFile()` 按需下载，并在 `docs/third-party-assets.md` 和页面「关于」里署名。

## 4. 模型怎么生成（一期）

风格和太阳系、几何体统一：柔和的卡通颜色、圆润外形、轻微高光，身体是半透明的「玻璃人」。

模型是**一个完整的人体**，由下面这些部件按真实位置拼起来，在场景里分成四层，剖开时由外往里一层层揭开：

1. **皮肤**：玻璃人外壳。
2. **肌肉**（简化）：胸腹部一层浅红色肌肉壳，只为「剖开」时有层次感，不分具体肌肉。
3. **骨骼**：头骨、脊柱、肋骨、胸骨、骨盆、四肢长骨（简化）。
4. **器官**：下表除身体轮廓和骨骼外的部分。

| 部位 | 生成方式 | 预计三角形 |
| --- | --- | --- |
| 身体轮廓 | 车削体做躯干，胶囊 / 球做头和四肢，半透明 + 边缘发光 | 6000 |
| 大脑 | 两个半球，顶点加噪声做出沟回；脑干和脊髓用管道 | 6000 |
| 心脏 | 变形的球（心尖朝左下），主动脉弓、肺动脉用管道；剖开时显示四个腔室 | 4000 |
| 肺 | 左右两片变形半椭球（左肺有心脏凹口），气管和三级支气管用分叉管道 | 8000 |
| 横膈膜 | 拱形曲面，呼吸时上下移动 | 800 |
| 食道、胃 | 沿曲线生成、半径可变的管道（胃是 J 形口袋） | 3000 |
| 肝 | 变形的楔形椭球 | 2000 |
| 小肠 | 沿程序生成的蛇形曲线绕成团的细管道 | 8000 |
| 大肠 | 倒 U 形粗管道，半径周期变化做出一节一节 | 4000 |
| 胆囊、胰腺、脾 | 小的变形椭球 / 长条管道，贴在肝、胃旁边 | 1500 |
| 肾、膀胱 | 两个变形成「蚕豆」的球、一个可胀大的球 | 2000 |
| 主要血管 | 主动脉、腔静脉几根粗管道（心脏演示时血液沿它流动），不做毛细血管 | 2000 |
| 肌肉壳（简化） | 躯干内缩一层的车削体 | 2000 |
| 骨骼（简化） | 头骨、脊柱节段、肋骨弧形管道、胸骨、骨盆、四肢长骨 | 8000 |

合计约 5.5 万个三角形。材质用 Lambert / Phong，不开阴影；粒子（血液、氧气、食物）用一个 `Points` 或 InstancedMesh 一次画完。

## 5. 功能规划

页面分两个标签：**身体探索**、**工作演示**。不做测验和打印；以后可选加一个「把器官放回家」小游戏。

### 5.1 身体探索

- **转、缩放**：单指旋转、双指缩放，和太阳系手势一致；底部有「正面 / 背面 / 侧面」快捷视角。
- **透视滑杆**：从「皮肤」到「骨骼」再到「只看器官」，身体逐渐变透明。
- **系统筛选**：全部 / 呼吸 / 循环 / 消化 / 泌尿 / 神经 / 骨骼，选中的亮起来，其他变灰、变淡。
- **一层层剖开**：「皮肤 → 肌肉 → 骨骼 → 器官」四个按钮（或一个滑杆），点一下外层淡出、往两边打开，露出下一层；可以随时合回去。
- **点器官**：器官高亮并轻轻弹一下，顶部出现名字标签，底部卡片只放三行：
  - 名字（如「心脏」）
  - 一句话：「身体的水泵，把血液送到全身。」
  - 打个比方：「和你的拳头差不多大。」
  - 心脏、肺、胃和肠子多一个按钮「看它工作」，跳到对应演示。
- **展开**：拖动「展开」滑杆，所有器官从身体里沿各自方向飞出来，在身体周围排开并显示名字；拖回去又回到原位（参考太阳系的展开）。展开状态下也能点器官看说明。
- **切开看里面**：心脏、肺、胃、大脑可以「切一刀」，用剖切平面露出内部（心脏四个腔、肺里的支气管树、胃的褶皱、大脑左右两半）。

### 5.2 工作演示

每个演示都是「一个大按钮 + 一句话旁白 + 一个能动手的地方」，旁白一屏不超过两行。

| 演示 | 动画 | 孩子可以做什么 |
| --- | --- | --- |
| 心脏泵血 | 心脏有节奏地收缩舒张；红色（含氧）和蓝紫色（缺氧）血粒子沿两条环路流动：心 → 全身 → 心，心 → 肺 → 心 | 点「跑一跑」心跳从每分钟约 80 次加快到约 120 次，粒子变快；屏幕上一个跳动的数字，可以跟着摸自己的脉搏数 |
| 肺呼吸 | 吸气时肺鼓起来、横膈膜往下、肋骨往外，蓝色氧气粒子进来；呼气时反过来，灰色二氧化碳粒子出去 | **按住屏幕吸气、松手呼气**，孩子跟着一起呼吸；连续 3 次后提示「氧气被送进血液啦」 |
| 食物旅行 | 选一种食物（苹果 / 面包），一个小球依次走过：嘴巴嚼碎 → 食道一挤一挤往下推 → 胃里翻搅 → 小肠吸收营养（营养粒子进入血管）→ 大肠吸水 → 排出 | 底部时间轴分 6 站，可以点某一站停下来看；每站一句话，并标大概时间（胃里 2～4 小时） |

演示都在同一个完整人体里进行：其他器官变淡，参与演示的器官亮起来，镜头自动转到合适的角度。大脑、肾脏等暂时只有点选说明，以后如需要再加「大脑指挥」「肾脏过滤」演示。

### 5.3 「把器官放回家」小游戏（以后可选）

身体只剩轮廓，底部一排器官图标，拖到正确位置会吸附并播放一小段动画；位置错了会轻轻弹回。用来检验「器官在哪里」，不计分、不出作业。

### 5.4 通用

- 首次进入每个标签有操作引导，「?」可以重看，做法和几何体、单位换算一样。
- 所有文案用 `t('中文')`，英文写进 `en.ts`；器官名字中英文对照，可以顺便学英文单词。
- 分享标题和分享图（`static/share/body.jpg`），工具箱图标（`static/tools/body.png`）都用脚本生成。

## 6. 内容与安全

- 只做一个中性的身体，不画生殖系统，不出现血腥、伤口。写实模型的皮肤去掉了外生殖器（像商场模特），换模型时也要这样处理。
- 颜色柔和（心脏珊瑚红、肺粉色、肝棕红、肠橙黄），避免写实暗红。
- 每个器官只讲一件事；数字用孩子能懂的比喻（如「心脏和你的拳头差不多大」），少用专业数字。
- 讲解文字自己写，不抄百科和教材原文。
- 页面底部一行小字：「示意图，不用于医疗判断」。

## 7. 性能与体积预算

| 项目 | 预算 | 做法 |
| --- | --- | --- |
| 分包体积 | 新增 ≤ 150 KB | 模型全部代码生成，没有图片和模型文件 |
| 三角形 | ≤ 6 万 | 见第 4 节；小肠等长管道按机型降低分段数 |
| 帧率 | 中低端安卓 ≥ 45 帧 | Lambert 材质、不开阴影、像素比上限 2；粒子 ≤ 600 个；静止 3 秒且无动画时降低刷新 |
| 内存 | 和太阳系相当 | 离开页面释放几何体和材质；切到后台暂停渲染 |
| 引导遮挡 | 不被画布挡住 | 沿用几何体的做法：引导非画布步骤时隐藏画布 |

需要在真机重点测：剖切平面（WebGL1 的 `clippingPlanes`）、半透明物体的排序、按住呼吸的触摸手势和旋转手势是否冲突。

## 8. 代码位置

放在 `src/subsolar/body/`，和 `cube/` 并列，共用 `subsolar/vendor/three.js`：

```
src/subsolar/body/
  index.vue       页面：两个标签（身体探索 / 工作演示）、介绍卡片、器官名单、引导
  anatomy.ts      部位清单（id、层、系统、颜色、展开方向）、身体坐标、消化道 / 气道 / 血液路线
  model.ts        BodyModel 接口：场景只认它，不关心模型怎么来的
  realistic.ts    写实人体：从云存储下载 body-v1.bin、缓存、解析成 BodyModel（带演示路线）
  procedural.ts   用代码生成的人体（一期，现在是下载失败时的兜底），实现 BodyModel
  scene.ts        three.js 场景、相机、手势、剖开 / 展开 / 切开、三个演示的动画和粒子
  lessons.ts      讲解文字、演示文案、引导步骤（中英文）
```

`pages.json` 在 `subsolar` 分包里注册了 `body/index`，工具箱 `tools.ts` 有入口，分享标题是 `body` / `bodyDemo`。

## 8.1 写实人体模型（已做）

代码生成的人体不够真实直观，2026-11-20 换成写实模型。第 3 节担心的体积、解码、风格问题这样解决：

| 问题 | 做法 |
| --- | --- |
| 来源和许可 | BodyParts3D 4.0（皮肤、肌肉、骨骼、大脑、心脏、血管、消化和泌尿器官）+ HuBMAP 男性肺 v1.4（BodyParts3D 没有完整的肺表面），都是 CC BY 4.0，可商用。页面「身体里有什么」卡片底部署名，登记在 `docs/third-party-assets.md` |
| 体积 | `scripts/build-body-model.mjs` 在电脑上挑部位、焊接顶点、meshoptimizer 减面到全身约 9.5 万个三角形，位置量化成 int16、法线 int8、索引 uint16，整个人约 1 MB（原始数据约 70 MB）。文件放云存储 `cloud-storage/body/body-v1.bin`，**不进代码包**，分包只多了约 5 KB 读取代码 |
| 解码 | 自己定的二进制格式（`UBM1`），不用 Draco / GLTFLoader，读文件就是几个 TypedArray，手机上几十毫秒 |
| 下载 | 第一次打开下载约 1 MB，存到用户目录，之后秒开；超过 20 秒或失败先用代码生成的人体，下次再试 |
| 性能 | 同屏通常 5～6 万个三角形、十几到四十次绘制调用，和太阳系同一量级；没有贴图、不开阴影 |
| 演示路线 | 食物旅行、呼吸、血液循环的路线由脚本从真实网格算出（食道、胃、肠的中心线，肺里的取样点，动静脉一节节连起来），写在模型文件头里，场景按 `model.routes` 走 |
| 儿童内容 | 皮肤上的外生殖器在脚本里删掉并补平（`mannequin()`），像商场模特；不带生殖系统器官 |

代码：`realistic.ts` 读文件并返回 `BodyModel`（`loadBodyModel()` 下载缓存，`parseBodyModel()` 解析）；场景只认 `BodyModel`，路线没有时用 `anatomy.ts` 的 `DEFAULT_ROUTES`。

改模型：改 `build-body-model.mjs` 里的部位清单或三角形预算，`node scripts/build-body-model.mjs` 重新生成。**每次改都要换文件名**（`body-v2.bin`，同时改 `realistic.ts` 的 `FILE`），再上传到两个环境的云存储，否则用户手机上的旧缓存不会更新。

以后想换成别的模型文件（例如 glTF）：写一个 loader 返回 `BodyModel`，部位按 `PartId` 分、坐标对齐 `anatomy.ts`、每个 piece 的原点在自己的中心、切开才看得到的内部放 `inner`，能带上 `routes` 最好，没有就要按新模型改 `DEFAULT_ROUTES`。
