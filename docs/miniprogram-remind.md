# 课前 15 分钟提醒

目标：用户在今日或日历里点某一节课旁边的闹钟并允许后，即使已经退出小程序，开始前大约 15 分钟也会收到一条微信「服务通知」。内容是这节课的计划名称、开始时间、地点和备注。

代码已经接上。通知要真正发出，还得把云函数 `api` 和 `remind` 部署到用户所在的云环境，并确认定时触发器是启用的。

## 为什么不能在小程序里自己计时

小程序进入后台后，页面里的 `setTimeout` 会停，不能靠它在 15 分钟后弹窗。微信也不提供「到点由系统本地通知」的接口。

要用**订阅消息**：用户先点一次「允许」，微信记下这个人还有几次可发额度；云函数按钟点扫描课表，到点调用微信接口把消息送到「服务通知」。

课的时间在云数据库 `families.snapshotJson` 里（含临时改时间、取消）。每个家庭成员的 `openid` 在 `users` 里。这两份数据够用来发提醒，不需要再为课程单独建表。

## 限制（个人主体、工具类目）

- 一般只能用**一次性订阅**，选不到「长期订阅」是正常的。长期订阅只对政务、医疗等公共服务类目开放。
- 用户每点一次「允许」，该模板增加 **1 次**发送额度。一天 3 节课，就要允许 3 次，额度可以攒着。
- 不允许就不会发。不能在进入页面时自动弹授权，必须是用户点击按钮。
- 订阅消息不能拿来做营销。这里只提醒已经排好的课。
- 模拟器和游客模式收不到服务通知。要用自己的 AppID，在真机的开发版、体验版或正式版上测。

## 1. 微信后台

1. 用已绑定云开发的小程序登录 [mp.weixin.qq.com](https://mp.weixin.qq.com)。
2. 「功能」→「订阅消息」→「公共模板库」，选用和上课提醒接近的模板。字段尽量是：课程名称、上课时间、上课地点、备注。
3. 选用后四个字段按这个顺序：计划名称、开始时间、地点、备注，类型用 `thing`。云函数会读模板正文里的键名。只有自动识别失败时，才把模板 ID 写进 `apps/miniprogram/src/domain/remind.config.json`。
4. 确认开发环境和正式环境都已开通云函数。定时任务要部署到用户实际连接的那个环境（体验版连 `VITE_CLOUD_ENV_DEV`，正式版连 `VITE_CLOUD_ENV_PROD`）。

怎样算做完：订阅消息列表里能看到选用的模板，并复制到了模板 ID。

## 2. 时间轴上的闹钟

按钮在 `apps/miniprogram/src/components/DayCourseList.vue`，今日和日历的课程色块上，课程图标上方，文案是「设置提醒」。只有还没开始的课才显示。

点一下调用 `uni.requestSubscribeMessage`。一次调用里同一个模板 ID 只能出现一次，所以点一次、允许一次，只给这一节课增加 1 次额度。已经开过的课再点，只提示「这节课会在课前提醒你」，不再弹授权。拒绝时提示「还没开启提醒」，下次仍要点这个闹钟才会再问。

模板 ID 和 thing 编号只改 `apps/miniprogram/src/domain/remind.config.json`。小程序和两个云函数都读这一份。后台模板写 `{{thing3.DATA}}` 时，`fields` 里填 `thing3`，不要带 `.DATA`。`templateId` 留空时，云函数按模板正文识别键名。改完执行 `npm run build:cloud`，再上传 `api` 和 `remind`。不要改 `index.js` 里的副本。

怎样算做完：真机点击闹钟会出现微信授权弹窗，点允许后提示已开启。

## 3. 单独做一个定时云函数 `remind`

不要塞进现有的 `api`。`api` 只在用户打开小程序、调用云函数时运行。提醒要在没人打开时自己跑。

目录：`apps/miniprogram/cloudfunctions/remind/`。源码改完跑 `npm run build:cloud`，打包脚本会把 `occurrencesOnDate` 打进 `remind/index.js`。

`config.json` 里加定时触发器，每 5 分钟一次。微信的 cron 是 7 段：秒 分 时 日 月 周 年。`permissions.openapi` 必须声明，否则云函数调微信接口会被拒（报 `-604101`），订阅能成功但永远收不到消息。

```json
{
  "permissions": {
    "openapi": [
      "subscribeMessage.send",
      "subscribeMessage.getTemplateList"
    ]
  },
  "triggers": [
    { "name": "tick", "type": "timer", "config": "0 */5 * * * * *" }
  ]
}
```

`api` 云函数也要有 `config.json`，至少声明 `subscribeMessage.getTemplateList`，否则订阅时读不到后台模板，存进去的模板 ID 是空的。

部署：在微信开发者工具里对 `remind` 选「上传并部署：云端安装依赖」。**上传函数不会带上定时触发器**，还要在 `cloudfunctions/remind/config.json` 上右键选「上传触发器」，再到云开发控制台「云函数 → remind → 触发器」确认能看到 `tick`。开发、正式两个环境各部署一次。

只上传了函数、没上传触发器时，订阅会成功，`reminders` 里也有 `pending`，但到点永远不发；过了开课时间记录仍是 `pending`，就是这个原因（定时器跑过的话会把它改成 `skipped`）。

怎样算做完：云函数列表里有 `remind`，触发器为启用，日志里能看到每 5 分钟一次的调用。

## 4. 每次触发时做什么

时区用 `Asia/Shanghai`，和现在家庭数据的 `timezone` 一致。

1. 只读 `reminders` 里状态为 `pending` 的记录。每条是某一个用户为某一节课点过允许。
2. 用这节课所在家庭的 `snapshotJson`，经 `occurrencesOnDate` 核对课还在，开始时间以临时调整后的为准。已取消或已开始则标成 `skipped`。
3. 开始时间落在现在之后 1 到 18 分钟里才发，也就是大约上课前 15 分钟。每 5 分钟扫一次。上课时间到了还没发出，就标成 `skipped`，不再补发。不是上课那一刻才推。
4. 只发给点过这节课闹钟的那个 openid。调用：

```js
cloud.openapi.subscribeMessage.send({
  touser: openid,
  templateId: '模板ID',
  page: 'pages/home/index?tab=today',
  miniprogramState: 'formal',
  lang: 'zh_CN',
  data: {
    // 键名不带 .DATA。模板里的 {{thing3.DATA}} 这里写 thing3。
    // thing3: { value: 课程名，最多约 20 字 },
    // time2: { value: '2026年10月12日 15:00' },
    // thing4: { value: 地点或「地点待定」 },
  },
})
```

`miniprogramState` 要和接收端一致，否则真机没有这条通知：

| 用户打开的版本 | 填什么 |
| --- | --- |
| 开发版 | `developer` |
| 体验版 | `trial` |
| 正式版 | `formal` |

5. 文档 ID 用「openid + 课程 ID + 日期」。发送前状态仍是 `pending` 才发，成功后改成 `sent`，避免下一个 5 分钟再发一遍。集合由云函数 `createCollection`，不必在控制台手建。权限建议「所有用户不可读写」。

发送返回 `43101`：这个人没有剩余额度。不要重试。等他再点「课前提醒」并允许之后，才会再有额度。

模板字段超长会直接失败。课程名、地点先截到模板允许的长度（`thing` 类型大约 20 个字）。

怎样算做完：手动云端测试一次，日志里能看到发出去或明确的 `43101`，而不是字段格式错误。

## 5. 用户侧会看到什么

1. 打开小程序，在这节课左侧时间轴旁点闹钟，弹窗里点允许。
2. 之后即使划掉小程序，课前大约 15 分钟，微信「服务通知」会出现这节课的名称、时间、地点和备注。
3. 点通知进入今天页。
4. 没点允许，或额度已经用完，这次不会推。每节课要点一次。

## 6. 上线前怎么测

1. 真机打开开发版或体验版，点允许。此时 `miniprogramState` 用 `developer` 或 `trial`。
2. 建一节开始时间在 15 分钟后的课。
3. 云开发控制台对 `remind` 选「云端测试」立即跑一次，或等到下一个 5 分钟。参数填 `{ "force": true }` 会不等 15 分钟窗口，立刻试发今天还没开始的课（用掉那次额度）。返回结果的 `rows` 里每条都写了 `sent`、`wait`、`skipped` 或微信退回的错误；失败原因也会写进 `reminders` 那条记录的 `lastError`。
4. 看云函数日志，再看手机微信的「服务通知」。
5. 同一节课再触发一次，确认 `reminders` 挡住了重复发送。
6. 正式版发布前把 `miniprogramState` 改成 `formal`，并部署到正式云环境。

## 7. 费用和以后的收紧

定时触发器按调用次数计费。家庭自用、每 5 分钟一次，一般还在云开发免费额度里。家庭或课程变多之后，再改成只扫描「今天有课」的家庭，避免每次把全部 `snapshotJson` 读出来。
